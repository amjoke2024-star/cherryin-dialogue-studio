# 产品溶图功能设计

## 目标

在现有“图片生成 / 图片改字”模式之后新增“产品溶图”。用户上传或沿用一张已经将产品放入场景的图片，通过矩形选区标明产品区域，再选择“真实校光”或“视觉优先”，由现有图片编辑模型生成光影和环境关系更加统一的图片。

首版重点是让产品自然融入场景，同时避免产品变形、品牌标识损坏、包装文字错误、产品数量变化或定位框出现在结果中。

## 用户流程

1. 用户点击输入区工具栏中的“产品溶图”。按钮位于“图片改字”之后。
2. 若已有上传图片，则沿用该图片；否则提示用户上传一张图片。
3. 页面展开产品框选工作区。用户在图片上拖出一个矩形框，并可移动选区、拖动四角调整大小。
4. 有效选区完成后，用户点击“下一步”。过小或无效的选区不能继续。
5. 用户选择一种处理方式：
   - 真实校光
   - 视觉优先
6. 用户可填写非必填的“补充要求”，例如“加强左侧暖光”或“产品不要变色”。
7. 用户点击“开始溶图”，系统固定生成一张图片，并保持原图宽高比。
8. 生成任务进入现有后台任务队列，并沿用现有进度、刷新恢复、历史记录和错误展示机制。

切换“图片生成 / 图片改字 / 产品溶图”时，已上传图片和尚未提交的产品选区应保留。返回重新选图时，仅清除当前产品溶图草稿。

## 界面设计

### 模式入口

现有模式按钮扩展为：

- 图片生成
- 图片改字
- 产品溶图

激活“产品溶图”时，上传提示改为“上传一张需要溶图的产品场景图”。模型仍使用当前支持图片编辑的 GPT Image 2 路径；生成数量固定为 1。

### 产品框选工作区

抽取一个通用矩形选区画布，供“图片改字”和“产品溶图”复用基础能力，业务状态和界面文案分别维护。

产品框选工作区包含：

- 原始图片画布
- 单个矩形产品选区
- 可拖动的四角调整手柄
- 可拖动移动的选区主体
- “返回重新选图”按钮
- “下一步”按钮
- 操作提示：“拖动框选产品区域，可移动选区或拖动四角调整范围。”

首版只允许一个产品选区。新画框会替换旧选区，避免多个区域导致提示语义不清。

### 处理方式面板

下一步显示两个互斥选项：

#### 真实校光

说明文案：“严格保留产品外观，只统一环境光、色温、反射和阴影。”

#### 视觉优先

说明文案：“保留产品核心识别信息，强化材质、高光和广告氛围。”

面板下方提供非必填的补充要求输入框，以及“返回调整选区”和“开始溶图”按钮。

## 数据模型

工作模式 `StudioMode` 增加 `product-blend`。

产品溶图草稿包含：

- `sourceImage`：原始图片
- `productBox`：归一化矩形坐标 `x / y / width / height`
- `blendStyle`：`realistic-lighting` 或 `visual-priority`
- `additionalPrompt`：用户补充要求，可为空
- `step`：`select-region` 或 `choose-style`

历史记录和待处理任务需要保存上述产品溶图信息，确保刷新恢复、历史展示和再次生成时可还原同一输入。用于模型定位的引导图属于临时参考图，不进入长期历史；原图需要进入持久参考图。

## 模型输入

提交时生成两张参考图：

1. 未修改的原图
2. 在产品选区外增加弱遮罩、并以醒目边框标出目标区域的定位引导图

引导图只用于定位。模型提示词必须明确指出第二张图片中的遮罩和边框不是画面内容，不得出现在结果中。

### 通用约束

- 编辑第一张原图，第二张图仅用于确定产品位置。
- 只处理选区内产品与周围环境的光影融合关系。
- 保持原图构图、镜头、宽高比和产品数量。
- 不生成选择框、遮罩、编号、箭头或说明文字。
- 不增加、删除、替换或复制产品。
- 不无故修改选区外的背景内容。
- 用户补充要求不能覆盖上述约束。

### 真实校光提示目标

- 严格保持产品轮廓、比例、结构、颜色、Logo、包装文字与图案。
- 分析背景的主光方向、光线软硬、亮度、色温和环境色。
- 调整产品的明暗关系、高光、漫反射、环境染色、接触阴影和空间遮蔽。
- 使产品看起来在该环境中真实拍摄，而不是粘贴在背景上。
- 不重新设计产品，不改变背景构图，不添加装饰元素。

### 视觉优先提示目标

- 保持产品主体、品牌和核心包装信息清晰可辨。
- 允许加强轮廓光、高光、反射、材质表现、环境色和广告氛围。
- 让产品自然进入场景，并获得精致的商业摄影效果。
- 禁止无意义变形、产品重复、Logo 替换和包装文字乱码。

## 生成与任务处理

产品溶图复用现有 `/api/generate` 图片编辑路径和后台任务生命周期：

- 只提交一个已有 `queueId` 的任务。
- 轮询只查询已有任务，不重新创建任务。
- 失败后显示服务端真实错误，不自动重试付费生成。
- 生成数量固定为 1。
- 输出比例跟随原图比例；分辨率沿用当前格式设置。
- 如果当前模型不支持所需图片编辑能力，自动切换到该 API 来源下的 GPT Image 2 默认模型，并在界面状态中反映实际模型。

## 校验与错误处理

- 无原图：提示“请先上传需要溶图的产品场景图”。
- 无选区：禁用“下一步”，提示“请框选图片中的产品区域”。
- 选区宽或高小于图片对应边的 1%：视为无效选区并提示重新框选。
- 未选择处理方式：禁用“开始溶图”。
- 定位引导图生成失败：不提交任务，保留原图、选区和用户输入。
- API Key 或模型不可用：沿用现有设置入口与错误提示。
- 任务失败：保留草稿，允许用户明确点击再次生成；系统不得自动再次收费。
- 刷新页面：恢复进行中的任务及其模式信息，不重复提交。

## 代码边界

实现应保持以下职责分离：

- 通用矩形选区组件：绘制、移动、缩放和归一化坐标。
- 产品溶图工作区：两步流程、模式选择、补充要求和业务校验。
- 产品溶图提示词模块：生成定位引导图并构造两种模式的模型指令。
- 页面状态与任务层：模式切换、提交、历史记录和刷新恢复。
- API 层：继续使用现有图片编辑接口，不新增另一套付费任务协议。

避免将产品溶图业务逻辑塞入图片改字组件；两者只共享无业务含义的矩形选区基础能力。

## 测试与验收

### 自动测试

- 归一化选区的创建、移动、缩放和边界限制。
- 过小选区校验。
- 两种模式提示词包含各自要求和全部通用约束。
- 用户补充要求被追加，但不能替换通用约束。
- 产品溶图任务固定 `count = 1`，保存正确的模式和草稿数据。
- 历史记录及刷新恢复保留原图、选区、模式和补充要求。
- 定位引导图不进入持久参考图。
- 失败和恢复流程不创建第二个付费任务。

### 本地验收

- 在 `localhost:3100` 验证三个模式入口及模式切换。
- 验证上传、框选、移动、缩放、返回、下一步和两种模式选择。
- 验证移动端或窄窗口下工作区可用。
- 运行测试、类型检查和生产构建。
- 重启本机正式服务后，验证 HTTP 200、页面入口和主要交互。

### 外部生成边界

开发验收默认使用本地模拟请求，不使用用户 API Key 发起真实付费生成。代码和本地流程验证通过后，由用户自行执行一次真实图片生成，确认模型对产品细节、定位引导图和两种风格指令的实际遵循程度。
