# 图片改字 MVP 设计

## 目标

在现有 CherryIN 对话画室的输入区增加“图片改字”模式。用户上传一张图片后，程序在本机浏览器中识别文字；用户点击文字框，只填写替换后的文字，即可调用当前已配置的 Image 2 编辑接口生成结果。

第一版用于验证“指哪改哪”的使用价值，不追求复杂排版参数或全自动多轮修正。

## 用户流程

1. 用户在输入区将“图片生成”切换为“图片改字”。
2. 用户上传一张 PNG、JPEG 或 WebP 图片。
3. 浏览器自动执行简体中文 OCR，并显示识别进度。
4. 图片上显示识别文字框；下方显示对应文字列表。
5. 用户点击文字框或列表项，填写新文字。原文字由 OCR 自动带入，但允许修正。
6. 用户可以选择多处文字，然后统一提交。
7. 程序把原文字、新文字及区域位置整理为明确的编辑指令，通过现有参考图编辑流程调用 Image 2。
8. 结果沿用现有生成记录、进度、预览与下载能力，并提供原图/结果对比和“继续修改”。

## 第一版范围

### 包含

- “图片生成 / 图片改字”模式切换。
- 单张图片上传。
- 浏览器内简体中文 OCR，覆盖常见中文、数字和英文字符。
- 图片文字框与文字列表双向联动。
- 原文字自动填充并可修正，新文字由用户填写。
- 多处文字同时提交。
- OCR 漏识别时手动拖框并填写原文字、新文字。
- 复用现有 API Key、Image 2 编辑接口、任务状态、历史记录和下载流程。
- 生成超时或下载失败时不自动重新发起付费请求。

### 不包含

- 字号、字重、字距、行距等不稳定参数。
- 自动多轮“精细模式”。
- Python、PaddleOCR 或 Windows 原生 OCR 依赖。
- 多张原图批量改字。
- 自动替用户重新生成失败任务。

## 技术方案

OCR 使用浏览器端 Tesseract.js，识别核心与简体中文语言数据随 Windows 包离线提供，不运行 Python 服务。OCR 仅用于读取文字与坐标，不产生 API 费用。

前端把 OCR 坐标换算为相对于原图的比例坐标，保证页面缩放后文字框仍能对齐。提交时将所选区域转换为“原文字、新文字、图片位置”描述，并复用现有 `/api/generate` 参考图编辑路径。第一版不新增独立模型接口。

## 状态与历史

图片改字任务在现有记录基础上增加模式、原图、识别区域和替换项。刷新后已提交任务仍可查看；“继续修改”恢复上一次替换信息。尚未提交的 OCR 草稿只保存在当前页面，第一版不承诺刷新恢复。

## 错误处理

- OCR 没有识别结果：提示用户手动框选，不调用 Image 2。
- OCR 识别错误：允许直接修改原文字。
- 未填写任何新文字：禁止提交。
- Image 2 生成失败：沿用当前错误分类，不自动重试。
- 图片已生成但下载失败：保留错误信息并提示不要直接重新生成。

## 验收标准

- macOS 和 Windows 浏览器使用同一套 OCR 代码，无需额外安装运行环境。
- 用户上传普通中英文海报后，可以点击一个识别框，只填写新文字并提交。
- 用户可以手动新增一个 OCR 未识别的文字区域。
- 图片生成模式的现有行为不受影响。
- 类型检查、单元测试和生产构建通过。
- 不执行付费实时生成，除非用户另行确认使用 API 额度测试。
