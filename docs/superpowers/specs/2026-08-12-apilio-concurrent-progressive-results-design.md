# 全供应商并发生成与逐张返回设计

## 目标

将所有图片供应商的多图任务统一改为最多四张并发生成。任意一张图片完成后立即显示，不等待全部请求结束。

## 当前问题

画室的后台任务接口当前使用循环逐张调用生成接口。Apilio 单张 2K 图片约需 76–84 秒，两张串行时正常耗时约为单张耗时的两倍。历史截图中的四次请求还包含刷新恢复造成的重复提交；该重复提交路径已在上一项修复中移除。

## 方案

### 统一调度策略

- Apilio、CherryIN 与 Black Forest Labs：同一任务请求 1–4 张时，同时启动相同数量的独立 `count: 1` 请求。
- Apilio 不使用单次请求中的 `n > 1`，避免供应商只返回一张或返回数量不确定。
- 如果供应商后台自行串行，画室仍会同时提交请求，但不承诺该供应商一定获得等比例提速。

### 逐张返回

每个供应商请求独立完成。任意请求成功后，立即调用现有任务状态更新函数，把图片追加到该任务的 `images`，并更新 `completedCount`。前端现有轮询读取到新图片后立即渲染，并显示已完成数量。

任务只有在所有并发请求均结束后才进入最终状态：

- 至少一张成功：`completed`，保留全部成功图片。
- 全部失败：`failed`，返回可见错误原因。
- 部分失败：`completed`，同时保留失败数量；前端继续使用“请求 N 张，实际成功 M 张”的提示。

### 安全与计费

- 每张图片只提交一次付费请求。
- 任何失败均不自动重试。
- 刷新页面只恢复对原任务编号的查询，不创建新任务。
- 任一供应商返回 429 或其他错误时，记录该请求的错误，不影响其他并发请求。

### 结果顺序

图片按完成顺序显示，先完成的图片先出现。最终历史记录沿用这一顺序，不为了恢复提交顺序而延迟显示。

## 测试与验收

1. 使用四个可控的模拟生成请求，证明四个请求在前一个完成前均已启动。
2. 模拟第二个请求最先完成，任务状态立即返回一张图片和 `completedCount: 1`。
3. 后续图片完成时依次返回 2/4、3/4、4/4。
4. 模拟一张失败、三张成功，保留三张并报告实际成功数量，不重试失败请求。
5. 模拟四张全部失败，任务进入失败状态并返回错误。
6. 验证 Apilio、CherryIN 与 BFL 均选择并发调度。
7. 运行测试、类型检查和生产构建。

自动验证不得调用 Apilio、CherryIN 或 BFL 的真实付费生成接口。最终真实耗时由用户使用下一次正常生成任务确认。

## 不在本次范围内

- 自动重试、指数退避或 429 后自动重新提交。
- 修改供应商、模型、质量或分辨率默认值。
- 让单个供应商请求直接生成多张图片。
