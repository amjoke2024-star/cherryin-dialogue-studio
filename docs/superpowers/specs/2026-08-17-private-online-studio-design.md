# CherryIN 私人在线画室设计

## 目标

将现有 CherryIN 本地画室迁移为可通过浏览器使用的在线站点，同时保留本地版。在线版采用邀请制访问，每位用户的数据和 API Key 完全隔离。

## 第一版范围

第一版保留现有画室的主要体验与功能：

- 图片生成、参考图上传和模型选择。
- 图片改字以及浏览器内离线中文 OCR。
- 生成任务进度、刷新后的任务恢复和部分成功结果。
- 电脑与手机浏览器适配。
- 邮箱邀请登录和退出。
- 每位用户独立添加、更新和删除自己的 API Key。
- 每位用户独立保存历史记录、上传图片、生成图片和任务记录。

第一版不包含公开注册、站内账号管理后台、套餐收费、余额统计、多人共享作品、本地历史自动迁移和自助找回密码。

## 访问与身份

站点使用平台提供的邀请访问与登录身份。站点所有者通过访问名单添加或移除用户邮箱。未受邀请的访问者不能进入画室。

服务端使用平台提供的稳定用户标识作为数据所有权依据。所有数据接口都必须在服务端读取当前身份，禁止信任浏览器提交的用户编号。

第一版不自建用户名和密码系统。这样可以避免维护密码散列、登录限速、重置密码和账户恢复流程。

## API Key 安全

每位用户保存自己的图片服务 API Key。API Key 在服务端使用站点主密钥加密后写入数据库，浏览器不能读取加密前或解密后的完整内容。

具体规则：

- 首次使用时由用户填写 Key，之后登录可直接生成。
- 只在服务端调用图片服务时临时解密。
- API 响应、错误信息和运行日志不得包含完整 Key。
- 页面只显示是否已配置及必要的掩码提示，不提供查看明文功能。
- 用户可以覆盖更新或删除自己的 Key。
- 删除 Key 后保留历史作品，但停止新的生成请求。
- 站点主密钥仅作为托管环境秘密配置，不写入代码、版本库或浏览器资源。

## 数据模型与存储

结构化数据存入云端数据库，至少包括：

- 用户设置及加密后的 API Key。
- 历史对话与生成记录。
- 生成任务状态、进度、错误摘要和恢复信息。
- 上传图片与生成图片的文件元数据、所有者和创建时间。

上传图片、参考图和生成图片存入云端对象存储。数据库只保存文件元数据和对象标识，不保存大体积图片内容。

每一条用户数据和每一个文件对象都必须绑定所有者标识。所有查询、修改和删除操作同时匹配资源标识与当前用户标识。

在线版从空白历史开始，不自动上传本地 `data/history.json`、`public/generated` 或其他私人文件。

## 生成任务流程

用户提交生成后，服务端读取当前用户的加密 Key、解密并调用所选图片服务。任务状态持久化到数据库，结果图片写入对象存储。

页面刷新后根据当前用户恢复仍在运行的任务和已完成结果。现有的以下行为继续保留：

- 多张图片可以逐张显示进度。
- 部分图片成功时保留成功结果。
- 失败请求不自动付费重试。
- 错误信息区分认证、余额、频率、服务异常和超时等常见原因。

长时间生成不能依赖单一进程内存。任务状态必须以持久数据为准，并设计为重复读取安全、重复提交不产生第二次付费请求。

## 图片访问

用户图片不使用永久公开链接。图片读取经过受保护接口，服务端检查当前用户是否拥有目标文件后再返回内容或短时可用地址。

文件名、对象路径或浏览器参数都不能替代所有权检查。修改网址不得访问其他用户的图片。

## 用户界面

保留现有 CherryIN 画室的视觉与交互结构，不重做产品界面。只增加必要入口与状态：

- 当前登录身份和退出入口。
- API Key 未配置、已配置、更新和删除状态。
- 云端保存与任务恢复的必要提示。
- 无权限、登录失效和 Key 无效时的明确反馈。

OCR 继续在浏览器内使用现有离线资源运行，识别得到的文字和坐标通过现有图片改字流程提交。

## 错误与恢复

- 未登录请求返回明确的未认证结果，不透露资源是否存在。
- 无权访问统一返回无权限或未找到，避免泄露其他用户的数据。
- 数据保存失败时不把未持久化结果显示为已保存。
- 图片写入成功但数据库写入失败时，记录可清理状态，避免产生长期孤立文件。
- API Key 解密失败时停止生成并提示重新保存 Key。
- 生成失败不自动重试；用户明确再次提交才会产生新请求。

## 部署结构

在线版作为独立的站点项目维护，不覆盖当前本地程序、启动工具或本地历史。站点使用：

- 平台邀请访问与用户身份。
- 云端数据库保存结构化数据。
- 云端对象存储保存图片。
- 托管环境秘密保存 API Key 加密主密钥。

上线时先保持邀请制访问。扩大访问范围或公开发布必须另行确认。

## 验收标准

上线前至少验证：

1. 未受邀请的访问者不能进入站点。
2. 两个测试账号只能看到各自的 Key 状态、历史记录、任务和图片。
3. 修改请求参数或图片网址不能跨账号读取或修改数据。
4. API Key 不出现在页面资源、接口返回、错误信息和日志中。
5. 用户更新或删除 Key 后行为符合预期。
6. 刷新页面能够恢复当前用户的运行任务，且不会重复提交付费生成。
7. 图片生成的部分成功结果能够保存并展示。
8. 图片改字和离线中文 OCR 在在线环境可以正常进入与提交。
9. 电脑和手机主要操作路径可用。
10. 构建与部署成功，线上受保护页面和数据接口正常响应。

实际图片生成会产生费用，因此自动验证不触发真实付费生成。最终由站点所有者登录后使用自己的 Key 完成一次真实生成验收，并单独记录该结果。

## 兼容与迁移边界

本地画室继续保留并可独立运行。第一版不保证本地版和在线版的历史双向同步，也不迁移已有本地历史或图片。未来如需迁移，应单独设计显式选择、预览、去重和确认流程。
